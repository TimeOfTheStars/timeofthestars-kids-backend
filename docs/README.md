## Два контура

**Публичный** — без авторизации. Читающие ручки отдают `Cache-Control: public, max-age=300`,
пишущие (заявки с сайта) авторизации не требуют, но и ничего не возвращают наружу.

**Кабинет** — префикс `/api/admin`, `Authorization: Bearer <token>` обязателен.

## Соглашение об именах полей

| Контур | Стиль | Пример |
|---|---|---|
| Публичный | **camelCase** | `goalsFor`, `isFinished`, `matchNo`, `fullName` |
| Кабинет | **snake_case** | `goals_for`, `is_finished`, `full_name` |

Это единственное различие в форме данных между контурами. Поле `city` пишется одинаково
в обоих.

## Идентификаторы и типы

- Все `id` — **UUID v4** строкой.
- Даты — `YYYY-MM-DD`, время — `HH:MM`, таймстемпы — ISO 8601 с зоной.
- Игровое время в протоколе — `MM:SS` **внутри периода**, а не от начала матча.
- Ссылки на файлы (`logo`, `photo`, `scan`) приходят абсолютными URL.

## Ошибки

Формат один на весь сервис:

```json
{ "detail": "Турнир не найден" }
```

| Код | Когда |
|---|---|
| `400` | Логическая ошибка запроса: нет полей для обновления, команда не в турнире |
| `401` | Нет или истёк токен кабинета |
| `403` | Роль `viewer` там, где нужен `admin`; отключённый пользователь |
| `404` | Объект не найден или скрыт с сайта (`is_visible = false`) |
| `409` | Конфликт состояния: занятый игровой номер, смена команд у заполненного матча |
| `413` | Файл больше лимита загрузки |
| `422` | Не прошла валидация — у Pydantic `detail` будет массивом объектов с `msg` |

Валидационная ошибка выглядит иначе, это стандарт FastAPI:

```json
{ "detail": [ { "loc": ["body", "phone"], "msg": "Field required", "type": "missing" } ] }
```
